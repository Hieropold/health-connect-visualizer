# ADR-0004: Read body composition from raw record tables, not `joined_body_metrics`

## Context

The export database includes a pre-joined convenience table named `joined_body_metrics`. While convenient, `joined_body_metrics` is an exporter-synthesised table rather than a standard Health Connect schema table.
Furthermore, `joined_body_metrics` stores timestamps as local-time strings (`date_time`), whereas all native Health Connect record tables (`weight_record_table`, `body_fat_record_table`, etc.) store timestamps as UTC epoch days/millis.

## Decision

Query body composition metrics directly from the raw record tables (`weight_record_table` left joined to `body_fat_record_table` on `local_date`) instead of using `joined_body_metrics`.
Empty string values in numeric columns are explicitly sanitized with `nullif(col, '')` prior to casting to `real` to prevent silent conversion to `0.0`.

## Consequences

- Guarantees compatibility with Health Connect DB exports generated by alternative export tools.
- Ensures consistent UTC date derivation across all dashboard panels.
- Prevents spurious zero values when body composition metrics are missing.
